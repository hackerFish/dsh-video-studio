# 内容标准层设计（Content Standards Layer）

> 目标：把「剧本质量 ↔ 平台评级对齐」与「2026 合规红线」变成鲸影可执行的机器化 check。
> 范围：只到「成片前文本段（故事/剧本/目录/卡点/合规）」+「分发前合规闸」。不改七段主链、不改供应商层。
> 本文是设计文档：给出每个 check 项的 输入/输出/阈值/出处/落点。实施时零新依赖（纯 TS + 注入式 LLM judge，对齐 `src/quality/review.ts` 既有双轨先例）。
> 阅读前置：`docs/ARCHITECTURE.md`、`docs/PROMPT-ENGINEERING.md`、`src/director/pipeline.ts`、`src/quality/review.ts`、`src/host/tools.ts`、`src/content/presets.ts`。

## 0. 事实基线（先检索，后设计）

设计所依据的事实全部带出处与「可信级」。可信级定义：

- **【A】官文/国家标准**：可到 nrta.gov.cn / cac.gov.cn / samr.gov.cn 原文核对。
- **【P】平台公开口径**：平台官方公告、平台官方创作课（红果短剧创作服务平台课程转载）、平台官方账号。
- **【I】行业方法论/情报**：公开拆解文章、开源方法论（short-drama, MIT）、媒体综述。
- **【T】待核**：仅有二手转述或任务上下文口径、未能获一手源——**T 级条款不落为硬阈值**，落为可配置项并在报告中显式提示「上线/申报前人工复核」。

## 1. 目标与设计原则

### 1.1 四个必须做对

1. **对齐评级**：评级是商业分账起点（P3/P4）。机器化 check 的目标不是「写得好」的抽象审美，而是「**平台收稿/评级的就绪度**」：故事完整性、人物塑造、价值观导向、市场适配（业务口径四维）+ 节奏（工业分镜可用性维度）。
2. **守住红线**：2026 监管=备案 + AI 标识 + 立意/导向 + 肖像与授权 + 题材禁区（R1–R6、P1）。红线项**机器先扫、LLM 判语义、人审兜底**，任何 P0 命中即阻断上传。
3. **不造假规则**：每条 check 标出处（§0 可信级）。无一手源的只落「待核配置」+ 报告提示，绝不硬编码成「官方」。
4. **不空谈**：每个 check 有 输入/输出/阈值/落点/测试。零新依赖，能单测。

### 1.2 复用既有骨架（不另起炉灶）

| 鲸影既有 | 本层如何对齐 |
|----------|--------------|
| `src/quality/review.ts`：ReviewCheck{item,status,detail} + 规则层先跑 + 注入式 Reviewer + retry/promote | 同构复制为「内容质检」：`ContentCheck` 双轨（Rule 轨 + 注入 LLM judge 轨），失败反馈带可执行 issues。**不新增依赖**。 |
| `pipeline.ts` `emit(stage,type,detail)` + `PipelineOptions.opts` 扩展点 + gate（auto/ask/manual） | 内容闸作为**段间 gate**挂在文本段之后，`contentGate` 从 `opts` 注入；事件走既有 `events`/`runs` 流（stage=`content`）。 |
| `host/tools.ts` 工具注册契约（name/description/parameters/output.schema/render/execute） | 新增 `whale_content_qc`、`whale_rating_readiness` 两个模型工具（主入口，agent 写完即自检）。 |
| `distribution/adapters.ts` PlatformSpec.compliance[] + ReleasePack 构建 | 分发前强制合规闸：compliance 数组升级为**可执行检查引用**（非提示文案），发布包不 ready 则拒发。 |
| `src/prompts/templates.ts`/`PROMPT-ENGINEERING.md` | LLM judge 的 rubric 用同一「区块化+可度量锚点」结构写成，可注入为普通提示词模板。 |

### 1.3 双轨模型

```
              剧本/目录/角色卡/整剧元数据（文本 + 机器可读摘要）
                                  │
                    ┌─────────────▼──────────────┐
                    │  Track R 规则轨（纯 TS）      │  确定性：词表/正则/结构/数值阈值
                    │  零成本、可单测、P0 词表硬扫    │  输出：{checkId, status, detail, loc}
                    └─────────────┬──────────────┘
                    ┌─────────────▼──────────────┐
                    │  Track L LLM 轨（注入 judge） │  语义：立意/人物弧/悬念回收/钩子有效性
                    │  无 judge 时降级=只报 R 轨+     │  输出：五维 0-20 + 证据句
                    │  标注「LLM 未接入」（对齐 review.ts）│
                    └─────────────┬──────────────┘
                    ┌─────────────▼──────────────┐
                    │  Score 合成 + 阻断判定         │  五维分（评级四维+节奏）
                    │  ContentVerdict → 回炉 or 过闸 │  阻断：结构红 / P0 命中
                    └─────────────┬──────────────┘
                                 ▼
              ① 工具面反馈给 agent（改写回炉 ≤2 轮）
              ② runPipeline 入口闸（rule 轨兜底，阻断成片）
              ③ 评级就绪度报告（分发/申报用）
```

## 2. 质检对象（工件契约）

QC 是「对文本成品的机器判断」，前提是**能稳定拆出结构**。鲸影文本段由 DSH agent 产出，需约定两套并存格式：

- **自由 markdown**（人/agent 都爱写）→ 用 `parse.ts` 解析，**解析失败 = 结构红 = 阻断**（逼回炉到规范格式）。解析器支持 short-drama 国内集格式与鲸影 `Script` 两种形态。
- **机器可读摘要 JSON**（agent 每产出一个文本工件同时附一份）→ 规则轨的**主要事实来源**。摘要缺失时，规则轨能跑的（词表/结构/数值类）降级到 markdown 解析结果，LLM 轨负责补语义事实。

### 2.1 工件清单

| 工件 | 形态 | 说明 |
|------|------|------|
| `DramaMeta`（整剧元数据） | JSON | 剧名/题材(genre 标签,可多选)/集数 N/受众(男频·女频·全年龄)/基调/结局类型/平台目标(抖音版权中心/红果…)/**备案类信息**(recordCategory: 重点/普通/其他; 备案号或平台备案号; 备案机关)/**AI 声明**(aiGenerated:true, 显式标识文案, 隐式标识文件)/**改编声明**(IP 来源、授权文件路径)/仿真人声明(虚拟形象登记)/逐集目录文件名表。 |
| `SeriesDirectory`（分集目录） | markdown + JSON | 每集一行：集号/标题/核心冲突或爽点一句/标签（🔥关键/💰卡点/常规）。JSON 侧为 `EpisodeIndex[]`（见下）。 |
| `EpisodeScript`（单集剧本） | markdown（场次结构）或 `Script{title,shots}` | 红果投稿口径 30 集试稿/70 集全本、每集约 1000 字（P5）。鲸影单条成片=1 个 `Script`。 |
| `EpisodeIndex`（每集机器摘要） | JSON | `{ep, tag, hookType(悬念/反转/情绪/信息/危机/无), endHook:boolean, scenes:number, firstSceneChars:number, opening:{narration:boolean, emptyScene:boolean, conflictIn30s:boolean}, beats:[{type:冲突/转折/爽点/揭秘/低谷/喘息/信息, intensity:1-5, atSec}], paywall?:{kind, freshSuspense:boolean}, dialogue:{maxLineLen, maxMonologue, totalChars}, summary}` |
| `CharacterSheet`（角色档案） | markdown + JSON | 每角：姓名/年龄/身份/动机/弧线(起→终)/与主角关系/爽点功能/反派层级(小/中/大/隐藏)。 |
| `StyleProfile`（风格与市场） | JSON | styleDna（接现有）、题材子类、对标竞品 2–3 部、目标平台、IP/原创标识。 |

> 说明：现有 `Script`（pipeline.ts）只有 title+shots(line/prompt/durationSec)，**没有集内场次与目录概念**——内容层在 `src/content/standards/types.ts` 定义上述工件类型，`parse.ts` 提供 `episodeScriptFromScript()` 把鲸影 Script 无损提升为 EpisodeIndex 的对话/结构事实（台词长度/镜头时长/首镜钩子等当场可查）。

## 3. 规则库（Track R）——每个 check 一项：输入/输出/阈值/出处/落点

约定：`severity` P0=命中即阻断；P1=必须整改后可过；P2=建议；P3=加分。`dim` 映射到五维（S1 故事完整性 / S2 人物塑造 / S3 价值观导向 / S4 市场适配 / S5 节奏）。`src` 标注出处可信级（§0）。所有数值集中在 `src/content/standards/thresholds.ts` 一处常量 + 版本号，改口径只动一处。

### 3.1 结构与台词（S5 基础，任何剧本先过此组）

| id | 输入 | 规则与阈值 | severity | 出处 | 落点 |
|----|------|-----------|----------|------|------|
| R-SHAPE-1 | EpisodeScript.md | 可解析：场次头完整、有场景/出场人物标注、短剧格式含 景别与台词指示；解析失败 | P0 | I | parse.ts |

## 4. 五维评分模型（评级对齐）

### 4.1 维度与权重

总分 0–100，五维各 0–20。评级四维为业务口径（§0.2 注），节奏维为生产/留存维度。维度权重可配置（`SCORE_PROFILE`），默认等权；红果/抖音版权中心如公开细则变化只改配置。

| 维 | 名称 | 主要来源 check | 说明 |
|----|------|----------------|------|
| S1 | 故事完整性 | R-SHAPE/R-RHY-3/5、R-HOOK-5/6、R-PW-8/9、LLM 悬念回收率与逻辑自洽 | 结构完整、悬念闭环、结尾收束 |
| S2 | 人物塑造 | LLM：动机/弧线/反派层级/爽点功能/女频独立人格 + R-SHAPE-2 字数支撑 | 对应角色档案工件评审 |
| S3 | 价值观导向 | §3.5 全组 | **P0 命中=该维 0 分且整体阻断**；P1 命中=该维 ≤10 |
| S4 | 市场适配 | §3.4 + §3.6 + P 平台口径（品类适配/收稿规则） | 平台收稿与评级就绪度主来源 |
| S5 | 节奏 | §3.1+§3.2+§3.3 | 分镜/留存可用性 |

### 4.2 合成规则

```
dimScore_d = clamp(0, llmScore_d(0-20) − rulePenalty_d, 20)
  rulePenalty: 每条该维 P1 fail −2，P0 fail −4；覆盖率：R 轨因缺摘要而未评的项计 −0.5/项（提示补摘要）
blocked = 结构红(P0) ∨ 任一合规 P0 命中 ∨ C-DIS 闸未过
overall = Σ dimScore（blocked 时仍给出供参考）
grade: S ≥90 / A ≥80 / B ≥65 / C ≥50 / D <50（内部档，勿直接对外声称=平台评级）
平台档位启发(仅内部,§0.2 注)：评估=「评级就绪度」而非评级结果。
```

### 4.3 LLM 轨（Track L）契约

对齐 `quality/review.ts` 的注入式 Reviewer：

```ts
// src/content/standards/types.ts（设计草图，非本次实现）
export type ContentKind = 'drama-meta' | 'directory' | 'episode' | 'characters' | 'style-market'

export interface ContentJudgeVerdict {
  /** 五维各 0-20 */
  dims: { story: number; character: number; value: number; market: number; rhythm: number }
  /** 每维一句话证据 */
  evidence: Partial<Record<'story'|'character'|'value'|'market'|'rhythm', string>>
  /** 合规语义结论（C-LI/C-POR/C-IP 系列） */
  redline: { id: string; ok: boolean; note: string }[]
  /** 语义类规则轨委托项（R-HOOK-5/6、R-PW-9/10、R-MKT-4…） */
  semanticChecks: { id: string; ok: boolean; detail: string }[]
}

export type ContentJudge = (opts: {
  kind: ContentKind; artifactText: string; summary?: unknown
}) => Promise<ContentJudgeVerdict>

export interface ContentGate { judge?: ContentJudge | null; maxRounds?: number; policy?: PolicyVersion }
```

judge 提示词用 `src/prompts/templates.ts` 的区块化模板产出（`content-judge` 模板，rubric 内容=§0.3 红果官方课 + §3.5 判定要点，含可度量锚点与证据句要求）。**无 judge 注入（默认）= 只跑 R 轨**，输出与报告都明确标注「LLM 未接入，语义维为结构代理分」——与现 `reviewShot` 无 reviewer 的行为完全一致（review.ts 先例）。

## 5. 接入点（三段式挂载）

### 5.1 A. 工具面（主入口，agent 写完即自检）

`host/tools.ts` 注册两个工具（契约与现工具一致）：

- `whale_content_qc`：`{kind, text, summary?}` → `{ok, blocked, score:{五维}, grade, checks:[{id,status,detail,loc}], redlines:[…], issues:[{severity,fix}], judge:'rule-only'|'dual'}`。model 每写完 目录/每集/角色卡 就调用一次。
- `whale_rating_readiness`：`{dramaId, 30集试稿?}` → 评级就绪度报告（§6），供提交/申报决策。

### 5.2 B. 成片管线入口闸（兜底）

`pipeline.ts` `opts.contentGate?: ContentGate`：

- `runPipeline` 在 story/script 事件之后、进入视觉提交之前，对 `script: Script` 跑 **R 轨 3.1/3.3 子集**（台词长度、首镜钩子、单镜时长、台词占比——Script 当场可判的项）；
- 结果走 `emit('content','gate',{blocked,checks})` 入 `events`/`runs` 流（UI 工作台可见）；
- P0 fail：gate=auto 直接 throw（阻断烧钱）；gate=ask 走既有 `ask()` 询问；manual 用户自决。**关键收益：外部/手动/预置脚本进视觉链前先被台词与结构闸拦一道，避免钱花在超长台词上。**

### 5.3 C. 分发强制闸（红线最后一关）

`distribution/adapters.ts` 构建 ReleasePack 时执行 §3.5.5 C-DIS-1：compliance 数组从文案升级为检查引用；任一 P0 → `ready=false` + issues 列出缺项（备案号/AI 标识/虚拟形象声明/授权文件）。新增 `hongguo` 平台 spec（9:16、单集上限、封面、红果口径限额配置）。

### 5.4 反馈与改写回炉（失败闭环）

```
agent 写完 ep5 → whale_content_qc(kind=episode)
  └ verdict.blocked=false 且 无 P1 → 过闸，进 storyboard
  └ 有 P1/P2 issues → 引擎把 issues（含 loc：第x场/第x句/第x镜）贴回给 agent
      → agent 按 fix 逐条改 → 重查（≤maxRounds=2 轮，对齐 maxRetries 语义）
  └ 2 轮后仍 P0/结构红 → gate 升 ask，交 DSH 审批通道人工裁决（审计留痕）
```

「改写回炉」定位在 **agent 对话内**（写→查→改→再查，工具即检查器），不占用视觉生成额度——这正是把质检前置到最省的环节。

## 6. 评级就绪度报告（RatingReadinessReport 雏形）

`whale_rating_readiness` 输出结构（对齐 runs/audit 的可审计风格）：

```ts
interface RatingReadinessReport {
  generatedAt: string
  dramaId: string
  meta: { title; genre[]; episodes; target: 'douyin-ip-center'|'hongguo'|'other'; model: '真人'|'仿真人'|'漫剧' }
  /** 五维评分与档位（§4） */
  score: { dims: { story; character; value; market; rhythm }; overall: number; grade: 'S'|'A'|'B'|'C'|'D' }
  /** 合规台账：P0/P1 逐条 + 对应字段/证据 + 政策版本 */
  redlines: { id; name; status: 'pass'|'block'|'fix'|'pending-check'; authority: 'A'|'P'|'I'|'T'; note }[]
  /** 平台就绪 checklist（按目标平台渲染）：
      - 备案：归类/备案号/片头标注（R1、2026-07-01 AI 分类口径）
      - AI 标识：显式+隐式（R2/GB 45438-2025）
      - 仿真人：虚拟形象声明/名人相似扫描/授权文件（P1）
      - IP/改编：授权类别/经典不颠覆（P1/P2）
      - 投稿形态：30 集试稿 + 窗口期 + 首卡点（P5/P6）
      - 立意结论：正向/需整改 + 证据（C-LI-1） */
  checklist: { item; required: boolean; done: boolean; authority }[]
  /** 商业档位启发（仅供内部，明示非平台承诺；政策波动风险提示 P7） */
  commercial: { band: 'S/A/B/C/D-就绪'; note: '保底与分成以平台当期签约表为准（2026-01 抖音版权中心口径 2-8万+20% 或红果六档）' }
  /** 平台内部评级规则未公开声明 + 人工确认点 */
  disclaimer: string
  audit: { policyVersion: string; judgeMode: 'dual'|'rule-only'; checksRun: number }
}
```

报告落盘建议 `docs/design/rating-reports/{dramaId}-readiness.json`（或 runs 台账扩展），作为**申报材料与内部评审的机器底稿**；人审只补「同意/驳回」一个动作，其余全部可机器复核。

## 8. 已知边界与最大风险

1. **口径易变且部分无一手源**：平台评级细则、保底表、审核规则未公开且按月波动（P7：2026-04/05 AI 仿真人保底传闻与否认；R4 综述 vs 官文细节）。对策=阈值/词表/政策版本全配置化 + 报告显式标注可信级；凡【T】不上硬闸。
2. **词表误伤正当表达**：合规隧道效应（硬词上下文敏感，如「复仇」题材名）。对策=硬词/语境词分层，语境词只触发 LLM 复核；P0 只给确定性词 + 人审兜底，不以词表替代审核。
3. **LLM 语义维的成本与可用性**：60–100 集 × 逐集语义判断=可观 token/额度。对策=judge 可缺省降级（rule-only），缺省时如实降分并标注；改写回炉发生在文本段（不烧视频额度）；judge 可挂豆包网页版 chat 适配器（现有 doubao-web SSE）或 DSH 会话模型。
4. **单集 vs 整剧的落差**：鲸影当前成片=单 `Script`；评级/投稿（30 集试稿/70 集完稿）是整剧尺度。对策=整剧工件（DramaMeta/SeriesDirectory/EpisodeIndex）成为一等输入，`Script` 提升为「单集脚本」；否则 QC 只到集，到不了评级。
5. **分级启发 ≠ 平台评级承诺**：S/A/B/C/D 档与商业启发仅供内部排序，报告声明「以平台当期签约表与评级结果为准」，避免误用导致商务误判。
