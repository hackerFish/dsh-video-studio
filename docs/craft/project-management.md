# 顶级项目管理 skill · 一人多项目运营的 PMO 方法论（鲸影 · 2026-09-04 v2）

> **定位**：张昌宇一人 + 求职期 + 多项目并行的"项目组合运营层"方法论——把四线（①鲸影 AI 仿真人剧系统开发 ②内容生产业务 ③novel-agent 网文 ④求职主线）当作**并行的项目**统一做产能调度、风险登记与节奏管理。本文 = 一人 PMO：不管理别人，管理"唯一的自己"在多项目间的分配。
> **方法论锚点（以国际源头为准，检索日 2026-09-04）**：PMI/PMBOK（项目组合 / 过程组）；Scrum Guide 2020（经验主义三支柱 Transparency/Inspection/Adaptation〔SCRUM-GUIDE〕）；Basecamp《Shape Up》（胃口/周期/Cool-down/下注桌〔SHAPEUP〕）；37signals《Rework》（planning is guessing / 拥抱约束 / 反工作狂〔REWORK〕）；GTD（可信系统〔GTD〕）；Cal Newport《Deep Work》+ Paul Graham《Maker's Schedule》（深工块与打断税〔NEWPORT〕〔MAKER〕）；Kanban（WIP 限制〔KANBAN〕）。个人多项目实证数据来自独立开发者英文实践报告〔ULRICH〕〔SS-2025〕〔GODNICK〕〔KAPIL〕。
> **边界（与同库文件分工，硬约定）**：
> - `producing.md` = **单部剧项目内**全流程制片：立项→预算→排期→质量门 G0-G4→申报→数据复盘。一部剧是一个"子项目"，内部规则引用它，本文不重复。
> - `business.md` = 对外商务/交易/合规（谈钱、签约、平台）。本文只做商务申报在时间轴上的占位与风险登记。
> - **本文只写"多项目怎么排、怎么管、怎么复盘"**：组合优先级、产能预算、跨项目风险、看板、节奏仪式、交付验收的跨项目口径。
> **分层标注（沿用本库硬约定）**：`〔KEY〕` = 检索到的真实来源（清单见附录 A）；`【一人+AI 落地】` = 单兵适配规则；`〔项目口径〕` = 项目 context/既有知识库提供、未复核数字，按保守档用。

## 0. 总纲：先管组合，再管项目（三条铁律）

**铁律 1 · Portfolio before Project（组合先于项目；计划要薄，判断要勤）**：PMBOK 明确一个项目可在"独立项目/项目集/**项目组合**"三种结构中管理，组合层回答"该启动/暂停/终止哪个项目、资源如何分配"〔PMBOK〕。Basecamp 给组合层的机制是**下注桌**：只在周期开始时对少数成型提案下注；**没被下注的提案就过期**——不设长期 backlog，因为它制造"进度的幻觉与义务的债"〔SHAPEUP〕。Rework 提醒"长期计划是猜测"：给方向与近期判断，别给假精确的远期排程，反复回到当前信息做决定〔REWORK〕。→ 单兵每周只回答一个问题：**下周这四条线，我为哪几条各下多少注**；暂停/砍线是被记录的决定，不是失败〔SS-2025〕。

**铁律 2 · 产能是硬约束，切换与打断是最大的隐性税**：知识工作者实测平均每 10-12 分钟切换一次工作域、57% 工作被打断；被打断后回神平均需 **23 分 15 秒**，人们用"做得更快"补偿中断，代价是压力与挫败显著上升〔GLORIA-2008〕。一人多项目实测每次跨项目切换开销 **13-29 分钟**（思维重置 5-10 分钟不可压缩），一天 6-7 次切换 ≈ 90-180 分钟蒸发；多项目不是 8×1 产能，是 4-5×，且只在有上下文重载工具时成立〔ULRICH-2026〕。Paul Graham 说得更狠：创作者需要至少**半日**的时间块，一次打断能把一个下午切成两段废料，甚至让你连早上都不敢开难活〔MAKER〕。Rework 把账算给你看：1 小时会议 × 5 人 = 5 小时没了〔REWORK〕——单兵版：**任何"顺手看一眼/临时被叫走"都按半日残废计价**。→ 所有排期先扣切换税再算产能。

**铁律 3 · 求职期求职 = 主线，其他线降档不消失；反工作狂**：制片是概率现金流（爆款率 ≈0.1%，见 producing.md），求职是确定现金流（现薪 23K → 期望 25-35K〔项目口径〕）。求职期默认求职占组合优先位，冲突先假设求职赢；推翻默认须在周复盘决策记录书面写明依据（§5.3）。同时记住 Rework 的警告：**多投入不等于多产出，加班是流程失序的症状不是解药**——单兵产能爆表时该做的是回 §1.2 切档位，不是"再撑一撑"〔REWORK〕。

### 1.2 "主线 + 副线"结构（下注语言）

- **任一时点只有一条主线**，主线拿 60-80% 深度时段；其余维护档或暂停档〔SS-2025〕。求职期主线 = ④；②③①降为副线（②常态 ≤40% 周产能上限〔producing.md〕）。
- 用 Shape Up 的"下注"语言替代"排任务"：**每周=一张小下注桌**，只问"下周为哪 1-3 注付产能、每注的胃口（愿付小时）是多少"；未被下注的想法不进永久池，丢回"将来/也许"——想再做就重新 pitch，过期是常态〔SHAPEUP〕〔GTD〕。
- **主线旋转是事件触发，不是日历**〔SS-2025〕：①转主线 = P0 闸门临近只剩收尾、或②数据已验证需引擎升级；②转主线 = 某剧过 G2 进批量期（先确认产能够）；④转主线 = offer 谈判启动（其余全线冻结增量）。**副线转主线必须经月度校准，不许当天拍脑袋**。
- 【一人+AI 落地】**副线≠烂尾**：每条副线保一个"最小心跳"（每周 ≤2h 或夜间批跑）——②的剧本夜间批跑、③的素材自沉淀、①的保持编译绿。

### 1.3 季度目标倒推（OKR × Shape Up 胃口 × Rework 薄计划）

- OKR 季度设定 1-3 个目标 × 2-5 个**可测**关键结果；KR 测结果不测活动（"跑 6 场面试"是任务，"offer ≥1 份且 base ≥25K"才是 KR）；0.7 达成即强；周 check-in、月校准〔OKR-INST〕〔OKR-PLAY〕。
- **胃口（Appetite）替代估算**：Shape Up 的核心翻转——不问"这个要多久"，问"我愿为它付多少时间"，**范围是变量，适配到胃口里**〔SHAPEUP〕。单兵周产能 22h 就是总胃口，各线下注 = 分胃口。
- **计划只做两层**：季度 = 方向 + KR（Rework：方向可以定，详细远期计划是猜测〔REWORK〕）；周期（见 §2）= 一页 pitch。中间不许长出假精确的甘特图。
- 倒推链：季度 KR → 月度闸门（月末校准）→ 周下注（周五复盘写下周 ≤2 条/线）→ 日小块。**倒推断了（周目标对不上 KR）= 方向漂移信号**，月校准必须处理。
- 【一人+AI 落地】季度示意：
```
O（≤2）: 确定性跳到 25-35K 档；同时保住鲸影 P0 与内容线不烂尾
KR1: offer ≥1 份且 base ≥25K（求职线，当前主线）
KR2: 鲸影 P0 三件套过闸（Provider v2/资产层/标准层）
KR3: ≥1 部剧过 G1/G2 至申报包就绪；≥1 部网文过评级分
```

## 2. 单项目推进框架

### 2.1 最小管理单元 = Shape Up 一页 pitch + 里程碑闸门

把 PMBOK 五大过程组（启动/规划/执行/监控/收尾〔PMBOK〕）与 Scrum 骨架（backlog→迭代→评审→回顾〔SCRUM〕）折叠进 Shape Up 的单兵变体〔SHAPEUP〕——**每个活跃项目先做一页 pitch，写清楚五件事**：
**问题（为什么做）→ 胃口（愿付多少周/h，不是工期）→ 粗略方案（边界即可，不做详细规格）→ 兔子洞（已知技术/业务风险，尽早侦察）→ No-go（明确不做什么，防范围蔓延）**
再加两个 PM 字段收口：**里程碑（3-6 个，各有交付物）→ 闸门（GO/NO-GO 二元条件）→ 周复盘（每周 10 分钟核对）**。
- **Backlog 三态**：活跃（本周下注）/ 维护（致命问题才动）/ 暂停（写恢复条件）〔SS-2025〕。**长期 backlog 是毒**：一屏放不下的清单 = 幻觉进度〔SHAPEUP〕——组合级根本没有总 backlog，只有各线的下一张 pitch。
- 【一人+AI 落地】**里程碑 ≠ 闸门**：里程碑是进度标记（"到哪了"），闸门是带后果的 GO/NO-GO 决策（"值不值得继续投"）〔WB-2026〕。每过一个里程碑强制停 20 分钟过闸，闸门条件写死在 pitch 卡上。
- **No-go 清单是最便宜的范围管理**：开工就写"本期不碰 X"，抵过十次开工后的纠结〔SHAPEUP〕。

### 2.2 鲸影开发：P0-P3 的周期、胃口与闸门（示例）

阶段命名沿用鲸影口径〔项目口径〕：P0 = 三件套改造（Provider v2 / 角色资产层 / 内容标准层，三份 design 文档 2026-09-04 已就绪）；P1-P3 后续阶段以当期里程碑清单为准。**本表给机制，不给假日期**：

| 阶段 | 里程碑（交付物） | 闸门（二元条件，全过才进下一阶段） |
|---|---|---|
| P0 三件套 | M1 规格定稿（3 design 文档评审） | G1：与真实 API 文档的事实核对表签认（禁闭门造车） |
| | M2 各层落地（Provider v2 适配 + 资产层 + 标准层 check） | G2：`tsc --noEmit` 零错 + `node --test` 全绿 + **v1 测试全保持绿**（向后兼容红线） |
| | M3 一部真剧走通新链路 | G3：产出样片与改造前对比证据（不劣于 v1） |
| P1-P3 | 每阶段同构 3 里程碑 + 2-3 闸门 | 规格门 → 编译/测试门 → 真证据门 |

**排日历规则【一人+AI 落地】**：
1. **先定胃口再拆里程碑**：给"P0-M2 落地"定一个上限（如求职期 3-4 周内可支付的深工小时数），范围（方言表先做哪几张/check 项先做哪几条）适配胃口，写进 No-go；超胃口 = 砍范围过闸，不是延胃口〔SHAPEUP〕。
2. **每个周期后留 cool-down/缓冲周**：Shape Up 在两周期之间强制 2 周冷却期——修 bug、还技术债、探索、为下周期做 pitch〔SHAPEUP〕。单兵版：阶段间留 1 周缓冲隙，只做维护/收尾/下期 pitch，吸收求职干扰，防连轴 burnout。
3. **廉价闸门每提交都跑**：`tsc --noEmit` + `node --test` 是几秒钟的事，不攒到阶段末——早期发现缺陷的成本比验收阶段低一个数量级〔WB-2026〕〔TEKREVOL〕。
4. **下注节奏**：周期开始即"下注"，周期内不再加注（求职突发事件除外，那是组合层改注）〔SHAPEUP〕。

### 2.3 单剧与网文子项目的挂接

②每部剧 = 一个子项目，pitch 直接引用 producing.md 制片卡（M0-M5 + G0-G4），组合层只登记：剧名 / 当前里程碑 / 下个闸门 / 本周下注小时。③每本书同理，闸门用其 QA 库口径。**子项目共享的产能是夜间批跑队列**：生成/渲染/审核批跑排夜间，人只做确认与抽检〔producing.md〕。**排队 backlog > 2 周 = 组合层信号**（加产能或砍承诺），不是项目内问题。

## 3. 产能管理

### 3.1 时间预算模型（胃口分配表，求职期示意，每周重算）

沿用 producing.md §3.1：求职期可控产能 ≈ **22 h/周**（工作日 2h×5 + 周末 6h×2〔项目口径〕）。这是**总胃口**，先切档位再切小时：

| 线 | 档位（求职期默认） | 胃口（示意） | 说明 |
|---|---|---|---|
| ④求职 | 主线 | 6-10h（面试周 12h+，其他线让路） | 投递/笔试/面试/复盘，随时可变档 |
| ①鲸影开发 | 副线-活跃 | 4-6h（深工块 2-3 个） | P0 闸门临近提到 8h，由④让出 |
| ②内容生产 | 副线-维护 | 2-4h（常态）~ 9h（封顶） | 夜间批跑不计人时；≤40% 周产能上限〔producing.md〕 |
| ③novel-agent | 副线-心跳 | ≤2h + 夜间批跑 | 保番茄分/追读不倒退即可 |
| 缓冲/休息 | — | 余量 | 面试突发、身体信号（R5） |

**执行规则**：胃口写进周一排期，周五对账。**实际 > 预算不是表扬，是组合 bug**——说明档位切错了，回 §1.2 重切〔REWORK 反工作狂〕。

### 3.2 深工的现实上限（≤4h/天）与 Maker's Schedule

- 多数人每天深度工作无法超过 **~4 小时**，把最高难度活排进个人能量峰值〔NEWPORT〕〔ASANA〕。周产能 22h 里深工至多 10-12h，**其余只能是浅工/批跑/杂务**——把任务分 深工/浅工/无人值守批跑 三类，别拿浅工占能量块。
- **Maker's Schedule**：编程与写作无法以小时为单位展开，至少需要**半日块**；一个插入的"会"能废掉整个下午〔MAKER〕。单兵没有同事开会，但面试、笔试、平台申报窗口就是你的"会"——见 §3.3 把它们聚成 office hours。
- 块长参考：一人多项目实测 **90 分钟块上限**——超过 90 分钟错误率与重试率明显上升；每天 4-5 个活跃 slot，其余线周级维护〔ULRICH-2026〕。强制到点停，保护"下个项目还想开始"的意愿。

### 3.3 切换成本、批处理与"office hours"策略

**先算税再排程**：跨域切换 13-29 分钟/次〔ULRICH-2026〕；回神基线 23 分钟〔GLORIA-2008〕。策略：
1. **按天/半天分块，不按小时切线**：一人多项目的共识是"按产品分天"远胜"每小时换项目"〔GODNICK〕〔KAPIL〕；每日跨项目切换 ≤2-3 次为上限【一人+AI 落地】。
2. **把一切可调度的打断聚成"office hours"**：Graham 在日末留一段集中接待外部预约，让会议永不打断创作块〔MAKER〕。单兵版：投递/平台申报/邮件/社交维护 = 每日固定 1-2 个浅工窗（如早 30 分钟 + 晚 30 分钟）；**面试与笔试安排进当天日末窗口**，深工块内永不接外部事务。"紧急的 90% 可以等 24 小时"〔KAPIL〕。
3. **切换留 5 分钟"落笔"**：切走前写 3-5 行"进度到哪/下一步/卡点"，回来自读即续——实测每次省 15-20 分钟重载〔ULRICH-2026〕（§6.3 同款纪律）。
4. **等待期是另一条线的产能**：样片等引擎排队、job posting 等回复 → 排另一线深工或浅工，别空等〔producing.md 夜间批跑哲学〕。

```
午 12:30-13:30  浅工窗：申报材料 / 知识库整理（能量低谷排浅工）
晚 19:30-21:00  深工块 B：副线下注（制片样片确认 / 鲸影编码 / 网文批跑后抽检）
夜 21:00 后     无人值守批跑 + 关机仪式〔NEWPORT〕
周末 4h×2      副线深工（制片 ≤40% 上限）+ 周五复盘 + 下周下注
面试/笔试日：当日副线清零、前 2 天减半（producing.md §3.3 求职冻结纪律）
```

## 4. 风险管理

### 4.1 跨项目风险登记（一册到底，Scrum 三支柱同构）

方法出处：风险登记册 = 一行一风险：ID / **因果式描述**（"因为 X 可能发生 Y，导致 Z"）/ 类别 / 概率 1-5 × 影响 1-5 = 分数 / 响应（规避/减轻/转移/接受）/ 状态；**触发后转 issue 处理、不删行**；随周复盘过一遍；放工作现场〔QUIRE〕〔WS〕〔ROCK〕。**五列的活册 > 十二列的死册**〔ROCK〕。
【一人+AI 落地】登记册只有一张（跨项目），owner 全部 = 自己，所以每行必须写**"最早可察觉信号"**——没有团队替你盯，靠信号前置。这套"看得见（登记透明）→ 定期查（周检视）→ 立刻调（触发即改注）"正是 Scrum 的 transparency/inspection/adaptation 三支柱〔SCRUM-GUIDE〕。

### 4.2 四线典型风险（初始登记，每周更新）

| # | 风险（因果式） | 类别 | 概率×影响 | 响应 | 触发线（信号） | 预案 |
|---|---|---|---|---|---|---|
| R1 | 平台政策摇摆（红果保底 2026 收紧实录见 producing.md §5③）→ 内容线账本假设失效 | 外部 | 高×高 | 减轻 | 双周扫描见公告变化 | 账本按保底=0；平台中立；现金可归零额独立〔producing.md〕 |
| R2 | 某剧评级失败/数据 NO-GO → 现金与士气双耗 | 项目 | 中×高 | 减轻 | G2 完播 < 对标腰部 50%（写死立项卡） | 止损即执行；复盘入库；禁"追加救上一部"〔producing.md〕 |
| R3 | 求职周期不可控拉长 → 现金流空窗 + 副线全停 | 资源 | 中×高 | 减轻+转移 | 连续 N 周 0 邀约（求职 skill 库定 N） | 作品集（鲸影/网文 = 面试弹药，双线互增强）；现金 ≥3 个月〔producing.md〕 |
| R4 | 鲸影技术延期（API 与 design 假设不符 / v1 回归）→ P0 拖过季度 | 技术 | 中×中 | 减轻 | 闸门连挂 2 次 / 核对表出新出入 | 规格先对真实 API 文档；廉价闸门每提交跑；**砍范围不砍闸门**（胃口思维） |
| R5 | 过载/倦怠（多线 + 求职压力）→ 全线质量崩 | 资源 | 高×高 | 接受+减轻 | 连续 2 周实际 > 预算 110% / 睡眠走差 | 90 分钟块硬限；每周 1 天不碰副线〔ULRICH〕；**每周期后 cool-down 周**〔SHAPEUP〕；记住 Rework：加班是失序症状不是美德〔REWORK〕 |
| R6 | 求职期副线"顺手多做一点"蔓延 → 挤占主线 | 组合 | 高×高 | 规避 | 周复盘发现主线实际 < 预算 50% | 维护档严格定义（§1.2）；超预算回 §1.2 重切，不在线内硬扛 |

### 4.3 求职期的特殊管理（两条互不伤害原则）

1. **求职不伤项目**：面试/笔试前 2 天 + 当天副线投入 = 0〔producing.md §3.3 冻结纪律〕；副线不得占用求职时段——一次面试的机会成本 = 数月副线流水。判断标准写死：**副线与求职冲突默认求职赢**，除非周复盘决策记录书面改判。
2. **项目不伤求职**：offer 谈判期不启动新 M1/新子项目〔producing.md〕；副线产出要"可包装成面试证据"——这是求职期做副线的最低效费比要求【一人+AI 落地】。
3. **预案是方向不是预测**：空窗拉长 → R3 触发 → 月校准二选一（全职求职 vs 边做内容线现金流边求职），写成**决策预案**：给方向与触发条件，不假装能预测结果〔REWORK〕，别在焦虑中即兴决定。

## 5. 看板与追踪

### 5.1 轻量看板（文件/Markdown 即可，透明是第一支柱）

Kanban 有效内核：可视化工流、限制在制品、拉式推进——列对应真实阶段，WIP 满了先清阻塞再开新卡〔KANBAN〕。Scrum 三支柱第一柱就是 Transparency：决策基于看得见的工件状态，看不见 = 风险〔SCRUM-GUIDE〕。单兵版【一人+AI 落地】：
- **一张组合看板**（§8.1）：四线 = 四行，状态列 = 活跃/维护/暂停/冻结 + 本周下注与风险列。周一起床先看这一页——这是你的"透明工件"。
- **每项目一页 backlog**：列 = `待办 / 本周 / 进行中 / 阻塞 / 完成`；**进行中整板 ≤3 卡**（跨线 WIP 上限），超了先收尾（拉式，不推式〔KANBAN〕）。
- **目录即工具**【一人+AI 落地】：
```
docs/craft/project-management.md   ← 本文（组合方法论 + 模板）
docs/craft/producing.md            ← 单剧制片（子项目规则）
portfolio/board.md                 ← 组合看板（每周更新，§8.1）
portfolio/weekly/2026-W37.md       ← 周复盘存档（§8.2）
portfolio/decisions.md             ← 决策记录（§5.3，追加式）
projects/jingying/p0-pitch.md      ← 鲸影 P0 pitch（引用 design/ 文档）
projects/content/ / projects/novel-agent/ / projects/jobhunt/
```
重工具（Jira/看板 SaaS）= 新增认知税不是效率〔KAPIL〕；Rework 提醒系统别搞太复杂——几个问题、一页纸，胜过一套没人维护的体系〔REWORK〕。

### 5.2 追踪指标（两周一看，不天天盯）

每项目两个数：**里程碑达成数/计划数**、**阻塞天数**（只减不加才健康）。组合层加：四线实际 vs 胃口（§3.1 对账）。不盯速度盯卡点——单兵瓶颈永远是等待/排队，不是手速【一人+AI 落地】。37signals 连速度指标都弃用：离活近到能直接看出"球两周没动"，不需要燃尽图〔REWORK〕——你离自己的活足够近，指标只是预警，不是考勤。

### 5.3 决策记录（为什么这么排）

GTD 说系统要"可信"才有效〔GTD〕；对单兵，可信 = 每个决定有迹可循。**任何档位切换、砍线、改主线、冻结解除，向 `portfolio/decisions.md` 追加一行**：`日期 | 决定 | 依据 | 否决的备选`。Rework：**做决定本身就是进展**——悬而未决会堆积，堆积的决策最后被无视〔REWORK〕。一周后回看"当时为什么把鲸影降档"有据可查，就不会在低潮期反复横跳。

## 6. 交付与验收管理

### 6.1 怎么定义"做完"（DoD，三层）

方法出处：DoD = 共识的"验收清单"，区别于笼统的"做完"——功能做了但没测/没文档 = 不算完成；验收标准开工前写下且可测〔SCRUM〕〔ATLASSIAN〕〔ZENTAO〕；DoD 描述增量完成，验收标准描述单个条目完成〔SCRUM.ORG〕。单兵最危险的词是"差不多"——**"差不多" = 未完成**，因为没有第二个人兜底。
【一人+AI 落地】三层 DoD：
- **任务级**：开工前写 1-3 条可测验收（"Provider v2 方言表新增一行后 `tsc --noEmit` 绿"），完成逐条打勾；
- **里程碑级**：交付物 + 质量阈值 + 资源确认 + 风险状态四要素〔WB-2026〕（例：P0-M2 过闸 = 编译零错 + 测试全绿 + v1 无回归 + 登记册无红项）；
- **项目级**：直接引用各线既有闸门（G0-G4 / 番茄分门 / offer 签署）。
**标准外延**：宁可砍范围（写进 No-go）也不降 DoD——砍范围 = 记录的决策；降 DoD = 无声的质量债【一人+AI 落地】。

### 6.2 拒绝返工原则

- 返工最贵处在"自以为做完"：规格阶段发现缺陷的成本比验收阶段低一个数量级〔WB-2026〕〔TEKREVOL〕→ **把 DoD 写进任务卡 = 把缺陷拦截在最便宜的位置**。
- 单兵三规则【一人+AI 落地】：① 验收标准开工前写，写不清 = 没想清，先想；② 里程碑过闸才宣布完成；时间到了该做的是**缩小范围过闸，不是带残品进下一阶段**（胃口思维〔SHAPEUP〕）；③ 同一类返工出现第二次 = 流程问题：先修流程（模板/检查项），别只修这一次。

### 6.3 文档化交接：一个人也要留痕（知识库 = 记忆）

切走前花 5 分钟写"到哪了/下一步/卡点"——交接对象 = 一周/一月后的自己；这是每次切换省 15-20 分钟的杠杆〔ULRICH〕〔SS-2025〕。37signals 的公司纪律直接可抄：**写下来优先于讲出来**，书面沟通强迫思维精确且留档〔REWORK〕。落地：
- 代码改动的理由写进 commit message（鲸影 4000+ 提交的既有纪律，保持）；
- 每个深工块结束写 3-5 行进度到项目 backlog"进行中"卡；
- 复盘、风险、决策全部落库（docs/ + portfolio/）——**知识库是唯一长期记忆**。检查标准：任一工作若中断一个月，能否凭文档 30 分钟恢复现场？不能 = 留痕不够。

## 7. 节奏与仪式（经验主义三支柱的多层反馈环）

Scrum 说透了一件事：**透明 → 检视 → 调适**，在多个时间尺度上自循环〔SCRUM-GUIDE〕；检视而不调适 = 白检视，调适而不检视 = 乱改〔SCRUM.ORG〕。单兵把三支柱落成四个尺度的仪式（都 ≤30 分钟，日历化）：

| 尺度 | 仪式 | 检视什么 | 调适动作 |
|---|---|---|---|
| 日 | 小步 5-10 分钟（三问自答） | 昨天/今天/卡点 | 当日块重排 |
| 周 | 周五复盘 30 分钟（§8.2） | 各线下注兑现/产能账/风险 | 下周重新下注 |
| 周期/月 | 月末组合校准 45-60 分钟 = 单兵版"下注桌"〔SHAPEUP〕 | 季度 KR 进度分（0-1，≥0.7 健康〔OKR-INST〕）、主线还对不对、风险全册 | 改主线/换赌注/砍线；写 heartbeat（上期做了什么）+ kickoff（下期做什么）一页纪要〔REWORK 周期仪式〕 |
| 季度 | OKR 重写（§1.3） | 方向还对不对（别闷头跑） | 下一季 1-3 O × 2-5 KR |

- **周仪式细节**：周一排期 20-30 分钟（从各线 pitch 拉卡进"本周"，填时间块模板〔SCRUM 计划会思想〕，排完当天不深工）；每日三问 = Scrum 站会三问（昨天完成/今天做/什么卡住〔SCRUM〕）对自己问，写 3 行再干活；周五复盘 30 分钟，**并入 GTD 周回顾**（收件箱清空、各项目"下一动作"明确、等待清单跟进〔GTD〕）。
- **仪式纪律**：仪式是时间盒不是待办，到点收；**连跳 2 次 = 系统信任崩塌的开始**〔GTD〕——最忙时恰是仪式最值钱时，真扛不住就降档副线把时间还给自己，别让仪式死掉。
- **Cool-down 也是节奏的一部分**：Shape Up 强制周期间留冷却期〔SHAPEUP〕，单兵版 = 每 4-6 周一个降载周（只保 2 条线 + 收尾技术债 + 做下期 pitch）〔ULRICH-2026〕——这是 R5 的结构性解药，不是可选项。
